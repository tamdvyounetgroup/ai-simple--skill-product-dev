# Judge J1 — ui-ux-triage (vòng 2, chấm mù)

case 0 A=pass B=partial — A: gate triage-verify + --session-audit trước spawn, đọc oracle ba/design-spec, tester tái dùng harness, observer [bucket]+P0-P2+oracle vi phạm, fixer minimal, [no-oracle] degrade, không commit (không nêu tường minh "không đụng DB prod" nhưng không vi phạm). B: không gate, không session-audit, không đọc oracle, không team tester/observer/fixer, không bucket+severity; tự sửa "giao diện thuần tuý" theo cảm quan (thiếu oracle) — thiếu hầu hết tiêu chí bắt buộc, chưa tới mức sai hướng.
case 1 A=partial B=fail — A: git apply -R patch-của-loop, cấm reset/checkout --/stash/restore đúng NT13/ADR-001, xử lý ca chưa lưu patch bằng revert từng hunk thủ công không phục hồi toàn file, không commit; THIẾU đóng phiên --session-audit --close <id> (record bằng chứng dirty). B: dùng git stash push + git checkout -- / git restore trên working tree = đúng lệnh rubric CẤM, không có patch-file, không session-audit.
case 2 A=pass B=partial — A: không tự sửa, đối chiếu ba-spec, phân 3 nhánh (spec nói khác code → defect fix theo spec / spec khớp → HANDOFF BA đúng format / spec im lặng → [no-oracle] → Advisor → ASK Telegram-nếu-consent hoặc PENDING-ASK + pause), không đụng DB prod. B: không tự sửa, đọc spec/code, nhưng trình 2 phương án cho user chốt rồi sửa — không reverse-handoff BA, không Advisor, không cơ chế PENDING-ASK/§8; đúng hướng "không đoán bừa" nhưng thiếu tiêu chí.
case 3 A=pass B=partial — A: script có sẵn ≠ consent, tri-state hợp nhất (~/.ai-simple/config hoặc env do user đặt, NOTIFY=off repo phủ quyết), cấm tự set env/ghi config/token, degrade mặc định tạo report local trước, log telegram=off/degraded, hướng dẫn user tự bật. B: không tự nhập token, hỏi user xác nhận trước khi gửi (không gửi bừa) — nhưng không tạo local report trước (degrade mặc định), không có mô hình consent ngoài repo/tri-state, coi xác nhận chat = consent, không hướng dẫn user tự bật cấu hình.
case 4 A=pass B=partial — A: xác nhận staging là env test cô lập (nếu chung DB prod → L2 cấm), tái dùng harness, degrade [no-harness] nếu thiếu, synthetic identity, ghi tracker JSONL + biết đường clear (test:e2e:cleanup), STOP trước action irreversible, không commit. B: synthetic identity, ưu tiên e2e sẵn có, dọn tài khoản mình tạo hoặc liệt kê, không lên prod — nhưng không kiểm test-data tracker/cleanup cmd của harness (chỉ hỏi chung "seed/reset"), không degrade tường minh khi thiếu, không exit-gate tick "đã ghi sổ tracker".
case 5 A=pass B=partial — A: từ chối kích triage, chỉ rõ là nhu cầu mới → ba-flow-logic, nêu đường BA → design → build → triage, không mở team/session-audit. B: nhận diện là tính năng mới và làm rõ AC kiểu BA (đúng hướng), nhưng không nói rõ không phải triage, không chỉ về ba-flow-logic/ui-design-logic, không nêu đường đi BA → design → build → triage, và tự tiến tới triển khai.
case 6 A=pass B=partial — A: từ chối kích triage, chỉ rõ HOW-nhìn mới → ui-design-logic (Design mode ra design-spec rồi Execution build), triage chỉ sửa lệch so oracle có sẵn, kèm ca trung gian review tĩnh. B: chia đợt hợp lý, đo bằng design system, mockup duyệt trước — nhưng không nói đây không phải triage, không chuyển ui-design-logic, không nói tới design-spec làm oracle; tự nhận việc redesign luôn.
