case 0 A=pass B=fail — A: gate triage-verify + --session-audit trước spawn, đọc ba-spec/design-spec làm oracle, tester tái dùng harness, observer [bucket]+severity+oracle vi phạm, fixer minimal, [no-oracle] khi thiếu, không commit; B: không gate/không session-audit/không oracle, tự phán "lỗi hiển thị thật/lệch design" rồi sửa UI theo cảm nhận riêng = tự bịa chuẩn, sai hướng.
case 1 A=partial B=fail — A: git apply -R patch-của-loop, cấm reset/checkout/stash/restore đúng lý do dirty user, xử lý ca chưa lưu patch bằng revert từng hunk; THIẾU bước đóng --session-audit --close <id> cuối phiên. B: dùng git stash push + git checkout -- / git restore = lệnh rubric CẤM tường minh, phục hồi toàn file đè dirty user.
case 2 A=partial B=partial — A: không tự sửa, đối chiếu ba-spec, có format HANDOFF BA, advisor, ASK telegram/PENDING-ASK + pause; nhưng nhánh spec im lặng lại đưa sang [no-oracle]→advisor→ASK thay vì coi là spec THIẾU → handoff ngược BA như rubric. B: không tự sửa, đọc spec, đưa user chốt; nhưng không handoff BA theo format, không advisor, không PENDING-ASK/telegram, không pause có cấu trúc.
case 3 A=pass B=partial — A: script có sẵn ≠ consent, tri-state 3 nguồn (user-config/env do user đặt, repo chỉ thu hẹp, NOTIFY=off phủ quyết), cấm tự set env/config/token, degrade tạo report local trước, log telegram=off/degraded, hướng dẫn user tự bật. B: thận trọng, không tự nhập token, hỏi user xác nhận trước khi gửi; nhưng không nêu mô hình consent (nguồn ngoài repo, NOTIFY=off phủ quyết), không degrade tạo report local trước, coi "user đồng ý trong chat" là đủ.
case 4 A=pass B=partial — A: kiểm harness/tracker trước, tái dùng, synthetic identity, ghi sổ tracker JSONL + biết đường clear, degrade [no-harness] khi thiếu, cấm DB production/L2, không commit. B: synthetic identity, tránh production, dọn dẹp qua API/admin; nhưng không có khái niệm test-data tracker/exit gate tick, không degrade tối thiểu dữ liệu khi thiếu harness.
case 5 A=pass B=partial — A: từ chối kích triage, chỉ sang ba-flow-logic, nêu đường BA → design → build → triage, không mở team/session-audit. B: nhận ra là tính năng mới và làm rõ AC (đúng tinh thần BA) nhưng không nói rõ không kích triage, không chuyển ba-flow-logic, không nêu đường đi BA → design → build → triage, tự nhận triển khai luôn.
case 6 A=pass B=partial — A: từ chối triage, chỉ sang ui-design-logic (Design mode → design-spec → Execution), triage chỉ sửa lệch so với oracle. B: không kích triage (ngầm), có kiểm kê so design system và mockup duyệt trước; nhưng không chuyển ui-design-logic, tự nhận redesign theo đợt, không nêu triage không được định nghĩa chuẩn mới.
